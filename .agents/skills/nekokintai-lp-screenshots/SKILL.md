# ねこ勤怠LPスクリーンショット

ねこ勤怠LPの3枚並びを壊さず、左右のアプリ画面だけを更新する。

## LPの不変条件

- 機能紹介は3枠構成を保つ。BGM関連文言の削除は、枠そのものを減らす指示ではない。
- 中央は `ねこがあるく` / `目標まで、てくてく` のままにする。
- 3枚は同じ外形・表示サイズに揃える。
- スクリーンショットだけの依頼で、本文、カード構成、CSSレイアウトを変更しない。

## 正本

- アプリリポジトリは既定でサイトの隣の `../nekokintai` を使う。
- `../nekokintai/docs/store/screenshots/final-1.png` から `assets/lp/screen-home.png` を作る。
- `../nekokintai/docs/store/screenshots/final-4.png` から `assets/lp/screen-shop.png` を作る。
- 中央の `assets/lp/screen-month.png` は外枠と表示サイズの基準として使う。明示依頼なしに変更しない。

生の720×1205キャプチャを直接LPへ入れたり、CSSで端末枠を足したりしない。切り抜き位置、角丸、合成位置を目測で決めない。スクリーンショット更新と同時にLPの文言や構成を変更しない。

このLPは、生キャプチャではなくApp Store提出用コンポジット内のアプリ画面を前提に作られている。生キャプチャをそのまま縮小すると、App Bar上の余白が消え、下部ナビが見切れ、中央画像と見かけの大きさがずれる。

## 再生成

サイトリポジトリのルートで次を実行する。

```bash
scripts/rebuild-lp-screenshots.sh
```

アプリリポジトリが隣にない場合だけパスを渡す。

```bash
scripts/rebuild-lp-screenshots.sh /path/to/nekokintai
```

スクリプトは以下の確定値を実装している。呼び出し側で再実装しない。

- 提出用画像から `952x1626+171+551` を切り抜く
- LP内寸へ `684x1164!` で変換する
- 半径17pxのマスクを適用する
- 既存フレームへ `+12+20` で合成する
- 出力を720×1205に固定する

提出用画像が古い、または目的のビルドを表示していない場合は、そのまま再生成しない。先に `../nekokintai/docs/store/screenshots/README-shots.md` を読み、対象ビルドから提出用画像を更新する。

## 検証

1. `identify assets/lp/screen-{home,month,shop}.png` で3枚すべてが720×1205であることを確認する。
2. サイトのテストとビルドを実行する。
3. デスクトップ幅とモバイル幅の両方でLPを実際に描画し、画像を目視する。
4. App Bar上の余白、下部ナビやフッターの見切れ、3枚の見かけの大きさ、外枠・角丸・影を確認する。

実画面を確認するまで完了とは報告しない。デプロイは依頼の範囲に含まれる場合だけ行う。
